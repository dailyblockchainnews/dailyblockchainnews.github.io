USDC transfers on Solana and Base: how fees differ

Solana vs Base for sending USDC: Solana usually has the steadier fee, while Base’s total moves with Ethereum data costs and whether the recipient is new.

The Hashbeam Desk·Nov 28, 2026 · 04:45 UTC·5 min read

Sending USDC usually costs a fraction of a cent to a few cents on either Solana or Base; Solana’s base fee is more predictable, while Base’s total changes with gas demand and the cost of posting data to Ethereum.

  • Solana charges a fixed base fee of 5,000 lamports per signature, plus any optional priority fee, in SOL.
  • Base charges for L2 execution and an L1 data fee, in ETH.
  • A first transfer to a recipient can cost more on either network because it may need to create a token account or storage slot.

These are fees for a single transfer on the network where the USDC already sits. Moving USDC between Solana and Base needs a USDC bridge; for more on native and wrapped USDC bridge tokens, see our article on what kind of token arrives at the destination.

How do Solana and Base calculate a USDC transfer fee?

Solana calculates the base fee from the transaction’s signatures, while Base adds its L2 execution cost to an L1 data fee.

On Solana, the base fee is 5,000 lamports for each signature. A plain wallet send commonly has one transaction signature, so its base fee is 5,000 lamports, paid in SOL. A sender can also include an optional priority fee to improve the chance the transaction is scheduled ahead of competing transactions. That extra amount depends on the fee settings and network conditions.

On Base, the execution portion is gas used multiplied by the L2 gas price, including any priority component. The transaction also incurs an L1 data fee for publishing its data to Ethereum. Both are paid in ETH on Base. The data fee depends partly on the signed transaction’s compressed size and Ethereum fee conditions, so a low Base gas price alone does not tell you the total.

That difference is why Solana is easier to estimate from its base fee, but not guaranteed to be cheaper in every case. Base’s fee varies with both activity on Base and data costs on Ethereum. The amount of USDC sent does not set either network fee; the transaction work and current fee conditions do.

Why can a first USDC send cost more?

A first send can cost extra because the recipient may need a new token-account record on Solana or a new balance slot in Base’s USDC contract.

On Solana, the recipient needs an associated token account to hold that USDC. If one does not exist, the transaction must create it, adding work and a setup cost on top of the transfer fee. Once the account exists, later sends to that recipient avoid that creation step.

On Base, the USDC contract stores each address’s token balance in a storage slot. Updating an existing nonzero balance slot costs about 5,000 gas at the storage-operation level; writing a new nonzero value to an empty slot costs about 20,000 gas. That additional gas raises the L2 execution part of a first send. The L1 data fee is separate, so the total still depends on the transaction data and Ethereum’s fee conditions.

This is the main edge case when comparing two everyday wallet sends: “same token, same amount” does not necessarily mean “same work.” If the recipient has never held that token on the network, the transfer may include account or storage creation. After that setup, subsequent sends can have a lower transaction cost.

Which network is cheaper for a typical send?

For an established recipient, Solana is often the easier low-cost choice to predict, while Base may be cheaper or more expensive depending on its L2 gas price and Ethereum’s data fees at the time.

Say you are paying someone who has already received USDC on both networks. On Solana, estimate 5,000 lamports per transaction signature, then add any priority fee shown by your wallet. On Base, use the wallet’s total estimate: gas used times the L2 gas price, plus the L1 data fee. Compare those totals in the same currency, using the same moment’s SOL and ETH prices.

For a new recipient, check the wallet estimate again before confirming. On Solana, token-account creation can change the cost substantially compared with a repeat transfer. On Base, a new balance slot increases gas use. The network whose established-recipient send is cheaper may not remain cheaper for that first payment.

For routine payments, choose the network the recipient can actually use and fund your wallet with its fee token: SOL on Solana or ETH on Base. Then compare the live total in the confirmation screen. Solana’s fixed signature charge gives it a steadier baseline; Base’s combined execution and data charges make its quote more sensitive to conditions.

What if the USDC needs to move between networks?

A transfer from Solana to Base, or from Base to Solana, is cross-chain and needs a USDC bridge rather than a plain same-chain send.

Circle CCTP supports both networks. A CCTP transfer involves a transaction on the source network and another on the destination, so budget for fees on both sides. The source and destination fees follow their respective networks’ fee mechanics: SOL-denominated charges on Solana and ETH-denominated charges on Base. This is separate from choosing the cheaper network for a single USDC payment to someone already using that network.

For a direct payment, compare the wallet’s current total and check whether the recipient already has a token account or balance slot. That gives you the practical answer: Solana is generally more predictable, while Base’s cost depends more on current execution and Ethereum data fees.
