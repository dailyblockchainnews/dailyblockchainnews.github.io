Hyundai Card tests AI treasury agents on Kinexys

Hyundai Card and Kinexys tested an AI treasury agent that requested FX to top up a euro account, with bank-side identity, mandate and control checks.

The Hashbeam Desk·Nov 22, 2026 · 06:56 UTC·3 min read

Hyundai Card and Kinexys by J.P. Morgan tested an AI agent that monitored a euro account, requested foreign-exchange quotes and sought a currency conversion to cover a balance shortfall. The proof of concept, described in Kinexys’s case study with Hyundai Card, used a test environment integrated with back-end systems; no real value was transacted.

The scenario set a minimum balance for Hyundai Card’s Frankfurt euro account. If the balance fell below target, its treasury agent would request quotes from three banks, select the most competitive and ask the chosen counterparty to execute a conversion using pounds from a named London account. CoinDesk’s report on the test also describes the flow as simulated transactions between hypothetical overseas subsidiaries.

The Hyundai agent made the funding decision and submitted the request; a separate Kinexys agent handled execution. That division leaves the client agent’s reasoning separate from the authority to release a transaction. J.P. Morgan says the proof of concept ran within Kinexys’s agent-as-a-service environment, so it did not test cross-institutional network connectivity or governance.

Authority was encoded in a machine-readable mandate. Hyundai’s principal generated a cryptographic key pair for its agent and registered the public key with Kinexys alongside an agent identifier and the legal entity represented. The agent signed outgoing messages with its private key. It could draft a proposed mandate, but the principal had to review and approve it in the Kinexys Portal before it took effect; Kinexys bound the approved mandate to that agent’s public key.

For each request, Kinexys checked whether the agent credential was valid, confirmed the principal it represented, and evaluated the request against the mandate’s currency pair, transaction size, limits and operating window. It also ran an AI-based assessment of whether the request fit the stated objective and appeared unusual. The goal, plan, action, checks and outcome were recorded in an audit trail. Only requests passing all checks were released for execution.

The controls produced three outcomes. A request within the mandate and below the principal’s escalation threshold could proceed automatically. A compliant request above that threshold was held for human approval; a request outside an approved parameter was denied. The test exercised all three paths: the normal funding flow, a request using an unapproved currency pair that Kinexys blocked, and an above-threshold amount sent for approval.

Kinexys’s paper calls the proof of concept deliberately narrow: one funding objective, one currency pair and direction, and two named accounts. It demonstrates a controlled workflow for identity, delegated authority and transaction checks around an agent’s request. It does not establish a live service or show real funds moving. The test’s significance for blockchain-based finance lies in how the bank governed an agent’s instructions around a Kinexys account, while keeping the transaction subject to a mandate and bank-side controls.
